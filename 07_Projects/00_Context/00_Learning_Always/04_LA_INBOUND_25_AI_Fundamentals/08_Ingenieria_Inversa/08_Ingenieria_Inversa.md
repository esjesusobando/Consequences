## ¿Cómo Funciona un LLM? (Deconstrucción)

### La Metáfora del Stereo

Dharmesh usa una metáfora efectiva:

```
想象: Una machine con miles de millones de knobs (como un stereo de los 70s)
- Cada knob puede subi o down
- La machine está "tuned" para predict la siguiente palabra
- That's "aprender" en AI
```

### Por Qué Esta Metáfora Funciona

| Elemento            | Equivalente LLM             | Por qué funciona               |
|---------------------|-----------------------------|--------------------------------|
| Knobs               | Parámetros (billones)       | Representan conocimiento       |
| Turning knobs       | Training                    | Ajusta probabilidades          |
| Stereo              | LLM                         | "Tuned" para una tarea         |
| Music output        | Texto/respuesta             | Resultado final                |

## El Marco PART

### Análisis de Origen

```
P = Prompt → Lo que el usuario escribe
A = Archive → Chat history
R = Resources → PDFs, imágenes, datos
T = Tools → Browser, APIs, code execution

TOTAL = Context Window = "Notas en Memento"
```

**Por qué "Memento"?**
- La película donde el protagonista no forma nuevos recuerdos
- Leaves notes/polaroids para si mismo
- AI hace lo mismo: el context windoweson sus "notas"

### Estructura Lógica

```
[INPUT: User Prompt]
    ↓
[Add: Archive (historial)]
    ↓
[Add: Resources (archivos)]
    ↓
[Add: Tools (capacidades)]
    ↓
[Context Window]
    ↓
[LLM Process]
    ↓
[OUTPUT: Response]
```

## La Regla 60-30-10

### Análisis de Diseño

```
60% REPETICIÓN (iteration)
- Keep doing what works
- Low risk, consistent value

30% ITERACIÓN (improvement)
- Improve existing prompts
-medium risk, higher reward

10% EXPERIMENTACIÓN (exploration)
- Try new things
- High risk, potential breakthrough
```

**Por qué 60-30-10?**
- Evita el extremas (100% repetición = stagnation)
- Evita el otro extremo (100% experiment = chaos)
- Balance práctico basado en product development

## TRIAGE → EXPERIMENT → AUTOMATE → MEASURE

### Análisis como Funnel

```
TRIAGE (filtrar)
→ ¿Qué casos importan más?
→ Frecuencia × Impacto × Lowfailure cost

EXPERIMENT (probar)
→ ¿Funciona?
→ Ajustar prompts y contexto

AUTOMATE (escalar)
→ ¿Funciona consistent?
→ Build agente

MEASURE (validar)
→ ¿Aporta valor?
→ KPIs reales
```

**Por quées un funnel?**
1. Many use cases → few winners (TRIAGE)
2. Few winners → some work (EXPERIMENT)
3. Some work → one scales (AUTOMATE)
4. One scales → value real (MEASURE)
