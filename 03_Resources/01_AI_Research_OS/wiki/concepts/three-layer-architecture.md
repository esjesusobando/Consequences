# Three-Layer Architecture

The AI Research OS is built on a three-layer architecture that keeps research data immutable, indexed, and intelligently synthesized — all using plain Markdown files.

## Layer 1: raw/ (Immutable Source Data)

The `raw/` folder contains the raw, immutable copies of all ingested data: articles, papers, video transcripts, repository clones, and any other source material. This layer is never touched by the LLM directly. It serves as the authoritative source of truth — the original content from which everything else is derived. When a new source is ingested, a raw copy is stored here, preserving the original exactly as found.

## Layer 2: index (Reference Catalog)

The `index.yaml` file is a catalog of all sources, wiki pages, and their metadata. It contains summaries of each source, authorship information, publication dates, and references to wiki derivatives. The index serves as the entry point for the AI agent — it tells the agent what exists, what it's about, and where to find it, without requiring the agent to read everything upfront. This is how the system achieves token efficiency: the agent can reason about what to read before reading it.

## Layer 3: wiki/ (LLM-Derived Synthesis)

The `wiki/` folder contains pages generated by the LLM from the raw sources. These include:

- **Concepts** — extracted key ideas with explanations, tags, and related connections.
- **Entities** — people, organizations, tools, and systems referenced across sources.
- **Comparisons** — side-by-side analyses of different approaches, tools, or architectures.
- **Sources** — executive summaries of each raw source, computed once during ingestion.

The wiki is *alive*: it evolves as new questions are asked, new concepts are extracted, and new connections are made between entities. Unlike a static research MD file, the wiki grows with usage.

## How the Layers Work Together

The query flow follows a strict hierarchy for token efficiency:

1. The agent reads `index.yaml` to understand what exists.
2. The agent reads source wiki pages (executive summaries) to find relevant information.
3. Only if the wiki is insufficient does the agent read raw sources.

This layered approach means most queries are answered without ever touching the raw data — keeping context lean and costs low.
